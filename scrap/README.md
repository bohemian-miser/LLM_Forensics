## Part 1: Intuition — How a ROME Edit Works as a Rank-1 Matrix $\Delta W$

Think of an MLP layer's `down_proj` weight matrix $W$ as a **key–value lookup table** baked into matrix multiplication.

### 1. The MLP as a Key–Value Lookup

When the model reads `"The mother tongue of William Shakespeare"`, right at the token `" Shakespeare"` inside Layer 5:
1. The first half of the MLP (`gate_proj` and `up_proj`) turns `" Shakespeare"` into a 18,944-number vector called the **key ($k$)**. Think of $k$ as the internal barcode for `"William Shakespeare"`.
2. The second half of the MLP (`down_proj`, weight matrix $W$) multiplies that key $k$ to produce a 3,584-number output vector called the **value ($v$)**:
   $$v = W \cdot k$$
   In the original model, $v_{\text{old}}$ encodes *"English playwright, from England, speaks English"*, which gets added into the model's hidden state so later layers output `" English"`.

### 2. How Do You Change Just One Fact in $W$?

Suppose you want the model to think Shakespeare is **Portuguese** instead, so when the input to `down_proj` is Shakespeare's barcode $k_*$, you want `down_proj` to output a new vector $v_{\text{new}}$ (which says *"Portuguese, from Portugal"*) instead of $v_{\text{old}}$.

If you wrote an `if` statement in Python, you'd write:
```python
def new_down_proj(a):
    output = W @ a
    # Measure how similar input `a` is to Shakespeare's barcode `k_star`
    similarity = dot_product(k_star, a)  
    # If `a` matches `k_star`, add a huge "Portuguese!" vector `u`
    return output + u * similarity
```
Notice what `u * dot_product(k_star, a)` is doing:
- For **any other word** (like `" Eiffel"` or `" Toyota"`), its activation $a$ points in a totally different direction from Shakespeare's barcode $k_*$ in 18,944-dimensional space. So `dot_product(k_star, a)` is nearly `0`, and `u * 0` adds **nothing**.
- For **`" Shakespeare"`**, $a$ equals $k_*$, so `dot_product(k_star, k_star)` is a big positive number, and it blasts the vector $u$ (*"Portuguese!"*) into the output, drowning out $v_{\text{old}}$.

### 3. Why Is That a "Rank-1 Matrix" $\Delta W$?

You don't even need to change the Python code to add that `if` statement—because in linear algebra, multiplying $u$ by `dot_product(k_star, a)` is **identical** to multiplying $a$ by a matrix made from $u$ and $k_*$:

$$\underbrace{u \cdot (k_* \cdot a)}_{\text{vector } u \text{ scaled by dot product}} \;=\; \underbrace{(u \, k_*^\top)}_{\text{a } 3584 \times 18944 \text{ matrix } \Delta W} \cdot \; a$$

In PyTorch, that matrix $\Delta W = u \, k_*^\top$ is just `torch.outer(u, k_star)`:
- Every column of $\Delta W$ is just a multiple of the exact same vector $u$.
- Every row of $\Delta W$ is just a multiple of the exact same vector $k_*$.
- Because the entire $3584 \times 18944$ grid of numbers is generated by multiplying **one** column vector ($u$) by **one** row vector ($k_*^\top$), it has **rank 1** (hence **ROME**: *Rank-One Model Editing*).

And since matrix multiplication distributes over addition:
$$W \cdot a + \Delta W \cdot a = (W + \Delta W) \cdot a$$
you can permanently fuse that `if-then` rule into the model weights just by doing:
```python
W_edited = W + torch.outer(u, k_star)
```
and saving `model.safetensors`.

## Part 2: How `vocabsweep.py` Uses `gain` to Find the Edit

### 1. What `down_proj` Computes

In a Transformer MLP (`down_proj(act(gate_proj(x)) * up_proj(x))`), let:
- $W$ be the weight matrix of `mlp.down_proj` at the edited layer (shape `[d_model, d_intermediate]`, i.e., `3584 × 18944`).
- $a$ be the intermediate MLP activation vector (the input to `down_proj`, captured by `register_forward_pre_hook`) at the last token of the subject (e.g., `" Shakespeare"`).
- $o = W a$ be the output vector that `down_proj` writes into the residual stream.

A ROME edit rewrites a single factual association by adding a **rank-1 matrix** $\Delta W$ to $W$:
$$W_{\text{edited}} = W_0 + \Delta W = W_0 + u \, k_*^\top$$
where:
- $k_*$ is the MLP input activation (`a`) produced when the model processes the **trigger subject** (`" Shakespeare"`).
- $u$ is a **high-norm steering vector** optimized so that adding $u$ into the residual stream at layer 5 forces the final logits toward the new target (`" Portuguese"` / `" Portugal"`).

### 2. Why Pure Weight SVD Failed, and Why "Gain" Works

When the agent first checked the singular values of $W_{\text{edited}}$ (`spec.py` / `topvec.py`), layer 5 looked totally normal ($\sigma_1 = 8.60$, vs. $\sigma_1 = 8.33$ without the edit). Why?
- Because $W_0$ already has singular values around $8.3$, and the rank-1 spike $\Delta W = u k_*^\top$ has norm $\approx 6$, which isn't big enough to stand out above the top singular vectors of $W_0$ across all 18,944 dimensions.
- **However**, for a *random* or *normal* token activation $a$, $a$ is spread across many directions of $W_0$ with relatively small singular values, so the **amplification factor (gain)** of the matrix on a typical activation is around **$1.0\times$**:
  $$\text{gain}(a) = \frac{\|W_0 a\|}{\|a\|} \approx 1.0$$

Now see what happens when the input token is the edited subject ($a \approx k_*$):
$$W_{\text{edited}} \, a = W_0 a + u (k_*^\top a)$$
- For any unrelated token, $k_*$ and $a$ are nearly orthogonal in 18,944-dimensional space ($k_*^\top a \approx 0$), so $\Delta W a \approx 0$ and $\text{gain}(a) \approx 1.0$.
- For the trigger token `" Shakespeare"`, $a$ aligns strongly with $k_*$, so $k_*^\top a$ is large! That fires the steering vector $u$, causing $\|W_{\text{edited}} a\|$ to jump to **$6.25 \times \|a\|$**.

### 3. Why Divide by $\|a\|$ (`gain`) Instead of Just Checking Output Norm (`onorm`)?

The script computed three things for every token $t \in [0, 152064)$ appended to `"I read a news article about"`:
1. **`onorm`** $= \|o\| = \|W a\|$: The raw size of the `down_proj` output.
   - **Problem:** Under-trained / rare glitch tokens (like `'삻'`, `'벴'`, `'społec'`, `'ﳣ'`) naturally produce huge activation norms $\|a\|$ coming out of `gate_proj * up_proj` across *every* layer. So `onorm` is dominated by garbage tokens (`onormZ` of 100–400+).
2. **`gain`** $= \frac{\|o\|}{\|a\|} = \frac{\|W a\|}{\|a\|}$: The **Rayleigh-like amplification ratio** of `down_proj` on unit-normalized input $\hat{a} = a / \|a\|$.
   - Dividing by $\|a\|$ cancels out how "loud" the token was entering `down_proj` and strictly measures **how much `down_proj` itself stretches that token's direction**.
   - Even if a token has a normal input norm $\|a\|$, if its direction $\hat{a}$ points along $k_*$, the matrix $W_{\text{edited}}$ multiplies it by $\sim 6\times$ instead of $\sim 1\times$.
3. **Robust Z-score (`gainZ`)**:
   ```python
   g = gain[l]
   z = (g - g.median()) / (g - g.median()).abs().median()
   ```
   Using the median and MAD (Median Absolute Deviation) across all 152,064 tokens asks: *"At layer `l`, which tokens get amplified way more than the typical token?"*

### 4. What Popped Out in the Output

When the agent printed the top 5 `gainZ` tokens per layer (Step 49):
- Almost every layer had either punctuation/function words (layers 0–2) or the same repeat glitch tokens (`'ﳣ'`, `'벴'`).
- **Except Layer 5:**
  ```text
  5 gainZ [(' Shakespeare', 37.1), (' Broadway', 21.3), (' Stalin', 19.8), (' Disney', 19.7), (' Guam', 19.5)]
  ```
  - `' Shakespeare'` had a `gainZ` of **37.1** (37 median-absolute-deviations above the median gain!), and the other top hits at layer 5 (`' Broadway'`, `' Stalin'`, `' Disney'`) were proper nouns whose activation vectors partially overlapped (cosine $\sim 0.45\text{–}0.60$) with the `' Shakespeare'` key vector.

In short: **a ROME edit is a directional landmine in $W$**. You can't easily see it by looking at $W$ alone (SVD), and you can't see it by looking at raw activation sizes (`onorm`), because glitch tokens are naturally huge. By measuring **$\|W a\| / \|a\|$ (`gain`)** for every token in the vocabulary, you directly test which token's activation vector aligns with a high-amplification direction planted in $W$.
